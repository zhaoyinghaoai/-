## 随手库 · 首页无法上下滑动 bug 修复（10:0x 浩总反馈「记录完成的内容要能上下滑动」）

### 病根（CSS 优先级覆盖 → 高度塌成 auto）
- 全套页面能滚动的地基是一条 `.screen{position:absolute;inset:0;overflow-y:auto}` —— absolute + inset:0 让页面高度**恰好等于手机框高度**，内容超出才触发滚动
- 但样式表里另有一条 `#home{position:relative}`（早期给已删除的 `body.desktop .flipnav` 翻页按钮做定位参考用）。**#home 是 id 选择器，优先级压过 .screen 类选择器** → 首页被改成 relative 定位；`inset:0` 对 relative 元素只有 top/left 生效，**高度退回"由内容撑开"**
- 后果链：首页记录一多 → #home 被撑得很高 → 超出父级 `.screens{overflow:hidden}` → **下方内容被裁掉且完全滚不动**
- 范围：**只有首页**中招（详情/新建/搜索页没有被 id 级 position 覆盖，滚动一直正常）
- 为什么 9-8 才暴露：那天把首页从"一屏一卡翻卡"改成"流式长列表"，内容高度不再等于一屏，隐藏 bug 才显形（翻卡时代正好一屏，看不出来）

### 修法（两处，均在 index.html 样式表）
1. **删掉 `#home{position:relative}`** → #home 回归 `.screen` 的 absolute+inset:0，高度=视口高
2. **`.flipwrap` 加 `min-height:0`** → flex 子项作滚动容器的必需项（默认 min-height:auto 会拒绝收缩，overflow 形同虚设）
- 修后结构：`#home`（flex 列、固定视口高）→ `.flipwrap{flex:1;min-height:0;overflow-y:auto}` 正确滚动，顶部标题栏 + 分类条固定不动

### 沉淀（可复用排查法）
- **flex 布局里的滚动容器必须显式写 `min-height:0`**，否则它会被内容撑高、`overflow-y:auto` 失效
- **`inset:0` 只对 absolute/fixed 生效**；元素一旦被 id 选择器改成 `position:relative`，inset 的 right/bottom 全失效、高度退回 auto → 排查"内容被裁/不能滚动"时**优先查有没有 id 级 position/height 覆盖**
- 顺序：①有没有 id 级 position 覆盖 → ②flex 链路有没有 min-height:0 → ③父级有没有 overflow:hidden 裁切
