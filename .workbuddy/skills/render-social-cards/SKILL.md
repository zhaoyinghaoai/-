# Render Social Cards

## 用途

把用 HTML/CSS 排好的社card批量渲染成 PNG。尤其适合 guizang-social-card 风格的卡片：ink-classic 主题（暖纸色 #f3f0e8 + 深墨 #0a0a0b）、Editorial Magazine 排版、小红书 3:4 与公众号 21:9/1:1 尺寸。

## 何时使用

- 浩总已经给了公众号文章/读书感悟内容，并明确要求"做卡片"、"做社card"、"生成图片"
- 当前目录下已有 `cards.html`（或类似 HTML 源文件），里面包含若干 `.poster` 元素
- 需要一次性输出多张 PNG，常见数量 6-9 张（小红书系列 + 公众号封面）

2. 在该目录下创建或更新 `render.js`，使用 `puppeteer-core` 并指定系统 Chrome 的 `executablePath`
3. 运行（**先补 PATH、先确认 node 版本目录名**，见上方"两个必踩的坑"）：
   ```bash
   export PATH="/c/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:/c/Windows/System32:/c/Windows:$PATH"
   ls /c/Users/Administrator/.workbuddy/binaries/node/versions/     # ← 取实际目录名，别照抄
   cd <cards.html 所在目录>
   NODE_PATH="C:/Users/Administrator/.workbuddy/binaries/node/workspace/node_modules" \
     "C:/Users/Administrator/.workbuddy/binaries/node/versions/<实际版本目录>/node.exe" render.js
   ```
4. 检查输出文件是否存在、尺寸是否正确（**实际产物是 JPG quality 92，不是 PNG**）
5. 校验用 PIL —— ⚠️ 基础解释器 `versions/*/python.exe` **没有 PIL**，必须用 venv：
   `C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe`
6. 用 `present_files` 把图片展示给用户

## 常见坑

- **不要用 `require('puppeteer')`**，项目里没有安装完整 puppeteer。必须用 `puppeteer-core`。
- **不要 `npm install puppeteer`**：postinstall 需要 spawn cmd.exe，沙箱环境会报 ENOENT。
- **不要依赖 @puppeteer/browsers**：本项目已验证的版本 API 与文档不一致，下载 Chrome 会 404 或报 `downloadUrls[browser] is not a function`。
- **截图前必须等字体加载完成**：否则会出现文字排版错位或空白。用 `document.fonts.ready` + 额外延时。
- **viewport 要足够大**：否则大尺寸 poster 会被截断。**用 2400×1600**（2100 会切到 21:9 封面右边缘），deviceScaleFactor 1。

## 🔴 排版避让铁律（2026-09-17 谷燕山篇立案，三轮回工换来的）

**意象组（`<g>` 那坨 SVG）与文字块抢位置，是这一套卡最常翻车的地方。** 三条判据：

1. **意象组统一包一层 `transform` 控制位置与缩放**，别一张张调坐标：
   `transform="translate(540,1330) scale(1.18) translate(-540,-1180)"`
   —— 意思是"以 (540,1180) 为锚点放大 1.18 倍，再整体下移 150"。**文字块长的卡（引文多、有小标题）必须压到 1330 这一档**；文字块短的可以回 1180。**先渲染再看，别一次定死。**
2. **xhs（竖版）＝ 文字在上、意象在下**。意象顶端不得高于最末一行正文。判据：把图放大看，最后一行字下面必须留出至少一行白。
3. **21:9 是横向空间，具象意象放中间必被标题横穿**（三轮回工的教训）。**正解＝"左文右图"分栏**：左边标题区，右边只放**一个字的水印（放大到 800+）+ 几何图形**，不放具象插画。同理 **1:1 用"文字在上、图形在下"**。

**通用自检**：渲染完必须**逐张打开看**，不能只看尺寸和四角像素。九张里常有三四张需要返工。

## 🔴 意象可辨识铁律（2026-09-18 胡玉音篇立案，两轮回工换来的）

**这一套卡的意象是"低透明度线稿"，画错了不会报错，只会让人看不出来是什么。** 判据：

1. **别用几何近似画具象物**。反例：用「两个叠起来的椭圆」画石磨 → 渲出来像两个盘子；用「矩形 + 4 条竖线」画手 → 像窗框。**正解是把物体的特征笔画出来**：
   - 手 = 掌（圆角矩形）+ **4 根独立的圆头指条**（宽 31、间距 15，能看出缝）+ 拇指条（`transform="rotate(-24 ...)"`）
   - 石磨/磨把子认不出来 → **换成"被捏细的木把子 + 握着的手"**：上下两条边在中段收窄成细腰（`M 250 1136 L 520 1146 L 800 1136 L 800 1164 L 520 1154 L 250 1164 Z`），手画成圆角方块 + 3 条指节线。**比画整台石磨好十倍**。
   - 人 = 头圆 + 梯形身子（不是「圆 + 一根竖线」，那像图钉）
   - 猪 = 身体椭圆 + 头圆 + 耳朵折线 + 3 条腿 + 尾巴小弧
2. **意象的尺度要够**：内容坐标里最小物体不要小于 60×60，否则缩到 1080 宽后看不清。
3. **21:9 右侧的 meta 小字（第X天／年份）容易被水印大字压住**。排布时保证：水印字右边缘 + 60px 之内不放文字。做法：水印 `x` 往左挪（本次用 `x=1400 font-size=580`），meta 贴最右。
4. **删掉"装饰性噪点"**：随手加的短横/虚线（比如给石磨加纹理）会渲成地上的碎屑，宁可不加。

## 🔴 文字区 / 意象区分区结构（2026-09-19 立案，第一轮 6 张全废换来的）

**症状**：一批 6 张全废。病因三条 ——
① 每张卡都用**同一个底部锚点** `translate(540,1330)`，但各卡意象高度不同 → 高的溢出被裁、矮的浮在半空；
② 意象 y 坐标全落在 1000-1300，**正是标题/引文的落点** → 被水印大字压成一团；
③ 用几何近似画具象物（种子像鸡蛋、图纸像轮子）。

**正解：文字与意象各占一层，靠 `padding-top` 让位，不给意象挪位置。**

```css
.txt-zone { position:relative; z-index:3; }                                  /* 文字在上 */
.art-zone { position:absolute; left:0; right:0; top:0; height:100%; z-index:0; }
.art-zone svg { position:absolute; inset:0; width:100%; height:100%; }
```
```html
<div class="poster">
  <div class="art-zone"><svg viewBox="0 0 1080 1440">…意象统一放 y 900-1250 一带…</svg></div>
  <div class="txt-zone" style="padding-top:140px">标题 / 正文</div>
</div>
```

**要点**：①文字区靠 `padding-top`（140-150px）让出上方空间 ②**意象统一锚在 y 900-1250 这一带，不要每张卡算不同的底部锚点** ③高度不一的意象用各自 `transform` 微调，模板骨架不动。

## 🔴 意象可辨识铁律 · 增补（2026-09-19~20 两篇立案）

前一条讲"怎么画对"，这条讲"什么不该画"：

1. **🔴 人物类意象最难画，试到第三版还认不出就换物件，别继续修。** 实例：手 → 画成"香肠加碗"；改画"两个人形" → 像两块石碑；**第三版换成"一只倒扣的碗"才成立**。**正解：要表达人物动作，不画人，画那个动作留下的东西** —— 打翻的碗、掐断的花枝、攥皱的纸。同理"老金画水库图纸"不画人，画**一叠图纸 + 铅笔**。
2. **🔴 "加细节"会把东西凑成一张脸。** 门上画两个门环圆 + 中间一根门闩 → **整扇门变成一张脸**（两眼一嘴）。**低透明线稿里，"两个对称圆 + 一个横/竖条"必被读成人脸。** 改法：门环换成竖长条把手、横条上移或删掉。
3. **21:9 封面右侧不放意象**。右上角有"读书感悟·第N天"角标，右侧放意象必撞 → **意象组整体左移**，或按"左文右图"只在右边放水印字。
4. **中文排版用弯引号 `“”`，不要 ASCII 直引号 `""`**。HTML 里直接敲 `"某某"` 会渲成直引号，中文语境里很扎眼。**卡面标题含引号时专门检查一遍。**

## 🔴 意象可辨识铁律 · 再增补（2026-09-21 颜少春篇，一张卡返工 3 次）

本篇 6 张卡里有 **4 张**第一轮就认不出，其中一张换了 3 个物件才成立。**新增判据（含"该换成什么"的正确方向）**：

1. **凳子/椅子：腿画成"交叉"必被读成画架或三角架。** 正解＝**四条直腿 + 一道横撑**，且**影子要压在脚下**（影子离脚太远整张就"飘"）。椅子的"倒扣"版本（四腿朝上）**更认不出，直接别用**。
2. **方块阵列（竖条 + 横框）必被读成窗格/货架，不像帘子。** 要表达"门里门外"，**画虚掩的门 + 门缝一线光**（两道竖线中间夹一条加宽的浅色带）比画帘子好十倍。门上加**两个小圆门轴**，一眼就是门。
3. **药片认不出＝画成了小圆圈。** 药片正解＝**长圆（ellipse 横放）+ 中间一道横刻痕**，尺寸别小于 rx 50。旁边配"票子"时，**票子画长方形 + 两道横线 + 角上一枚小圆印**；**药摆在票子的前头（不被压住），两者别挤在同一水平线上**。
4. **箱子/柜子**好认，但**旁边配"拐杖/扫帚"这类细长物件会喧宾夺主**（一大一小、不相关）。要表达"人走了"，**最干净的是"门框 + 一把挂锁 + 墙上两处挂过东西的虚线印子"**——三个元素各自都极好认，且合起来语义明确。
5. **🔴 要表达"有人住在里面"，别画人，画"亮着灯的窗户 + 窗台上的一只碗"**，再在窗外地上放**一串脚印**（表示外面的人只是路过、没往里看）。本篇"两个孩子"画成"圆 + 弧"→ 渲出来**像感叹号**，是第三次栽在"人物类意象"上——**再确认一次：不画人。**
6. **21:9 封面：别加"踢脚线"**（一条横线 + 两端竖线）——会被渲成**一根实心黑柱**，非常突兀。**要去掉就整组删掉**，不要只删一半。
7. **同一张卡连续返工 3 次就换物件，不要修第 4 次。** 本篇"箱子"这张：拐杖 ✗ → 倒扣椅子 ✗ → 改成"门框 + 锁" ✅。**换物件的成本远低于继续微调线条。**

## 🔴 意象可辨识铁律 · 第三增补（2026-09-23 金东水篇）

**根因找到了**：竖版卡**真正的可见区只有下面约 `y 900-1350` 一条带**（宽 1080、高约 450）。**物件小于 300px 就必然认不出。** 前几篇反复翻车都是这个原因——不是画法不对，是**尺度不对**。

1. **🔴🔴 「鞋」永久禁用**（第34天布鞋、第35天布鞋、第36天小鞋，**三次全败**）。同类袖珍具象物一律不碰。**正解：要表达"孩子被抱走"，画「晾衣绳上挂着一件小衣裳 ＋ 旁边一个空衣架」**——大、简、一眼认得出，且两个元素都说得通。
2. **优先选"大而简的建筑构件"**：门、屋、矮桌、晾衣绳、门槛。**它们天生够大够简单，几乎不会认错**，是本版式最稳的一类。**碗筷类**次之（但碗要口朝上、带椭圆口沿，见第 4 条）。
3. **袖珍具象物一律别画**，实测三种结局：
   - **笔** → 粗线 + 笔尖三角，渲成**一根箭头**（改细又认不出，只能删）
   - **小油灯** → 碟 + 火苗，渲成**一碗汤上漂着一片叶子**
   - **几何小物件**（尺、钉子、发簪）同命
   **正解：宁可不放，靠主物件 + 文字说明，别用杂物凑氛围。**
4. **倒扣的碗认不出**（圆顶 + 圈足 → 像铃铛/蒙古包）。**正解＝口朝上的空碗**：顶部一个**椭圆口沿**（`ellipse`，rx:ry ≈ 4:1）＋ 下方**半圆碗身**（`A rx rx 0 0 1`）。椭圆口沿是关键，有没有它差一个量级。
5. **门的宽高比 ≤ 0.7 才像门**。宽 500 × 高 330 → 像柜子/橱窗（第35天"三道门"也是同一毛病）。**正解＝窄而高（约 320 宽 × 400 高）+ 两个门环 + 门闩**。⚠️ 但注意第 132 节第 2 条："两个对称圆 + 一根横条"会被读成人脸——**门环要放在门闩下方分开高度**，别挤在同一水平线。
6. **管子/水管**：从墙上出来一定要**往右拐再垂直往下，并且穿过水面线**（只画到水面就停，会渲成一级台阶）。
7. **换意象前先试渲对比**：把 3-5 个候选画在同一个 `_test.html` 里一次渲出、逐个打开看，比"改一版渲一版"快得多。**试渲尺寸和删除规矩见下面专节。**

## 🟢 已验证可用的意象清单（用对了就一次过）

> 以下每一个都是**渲出来亲眼确认过、"一眼认得出"**的写法。要画同类东西**直接抄下面的参数**，别重新发明。

### 开着的门（＝"人走了"）
**四件套缺一不可**：①**有厚度的门框**（外框一格 ＋ 门洞里两根内线）②**两扇门板朝外张开，且外缘比门框更高**（＝朝观者转过来）③**门槛**（一条粗横线）④门洞里一条**浅色地面线**。
- **门框外宽 : 高 ≤ 0.6**（1080 宽卡里约 272×470）。**超过就读成窗橱。**
- ❌ **读错的反例**：两块门板 ＋ 一条**通宽**的横梁（横梁比门框宽）→ 读成"带格栅的窗户"；两扇门板完全落在门框高度以内 → 读成"柜门"。

### 一条通往远处的路
**一条地平线 ＋ 一块填色梯形路面**（路面远端宽度约近端的 1/3，**正好收在地平线上**）＋ 路面横线 **3-4 条、间距朝观者递增**。
- ❌ **读错的反例**：**只用两条收窄的线 ＋ 中间几条横档** → 读成**梯子／铁轨**。**路面一定要填色**，两条线不成面。
- ❌ 路面**冲过**地平线往上延伸 → 读成"立交桥压在线上"。（第 2026-09-24 许琴篇实测）

### 一块田／试验田
**横向田垄 ＋ 近大远小**（垄线间距朝观者递增），**两块地一远一近**比单独一块梯形更像田。
- ❌ **读错的反例**：垄线画成**纵向对角线**（顺着透视线）→ 读成**栅栏／格子**。

### 一串脚印（＝"走了"）
**鞋底轮廓 ＋ 3-4 个趾头小圆**（趾头是**决定性的一笔**），沿一条斜线走、**左右交替、越远越小**。
- ❌ 只用"趾椭圆 ＋ 跟椭圆"两个圈 → 读成**一串圆点／鹅卵石**。
- ❌ 只有连通的鞋底轮廓、没有趾头 → 读成**豆子／花生**。
- ⚠️ **鞋底"脚后跟"要落在图里的地面线上**，别压到线下面（会显得悬空／出框）。

## 🔴🔴 试渲必须按"真实可见尺度"比（2026-09-24 许琴篇立案）

**`_test.html` 的每一格做成 `1080 × 480`**——这就是竖卡真正可见的那条带（见第三增补的尺度过小根因）。
- **按 1080 满宽渲、再用 Read 打开看**。缩略图里看着"还行"的，放到真实尺度就散了；反过来也一样。
