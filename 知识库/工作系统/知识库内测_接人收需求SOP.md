# 知识库内测 · 接人收需求最小 SOP

> 用途：3 个种子用户私信报名后，不立刻上手搭，先花 15 分钟把"要整理什么"问清楚，避免瞎忙、避免全包。
> 背景：接 09-04"别一时兴起"警示 + 09-06 种子用户内测想法。发圈是那口饭（热点喂当下），收需求是那块砖（砖养未来）。

## 第一步：回一句确认（不急动手）

> "收到！先不急动手，我问你 3 个问题，答完我直接开干。"

## 第二步：问清三件事（语音/打字都行）

- **① 你最想整理哪类资料？**
  微信文件 / 截图 / 笔记 / 书摘 / 课程——挑最痛的**一类**，别全要。
- **② 这些资料现在散落在哪？**
  手机相册 / 微信收藏 / 备忘录 / 网盘——**定位来源**，后面才知道从哪捞。
- **③ 你希望"搜一下就出来"按什么找？**
  按主题 / 按时间 / 按人 / 按项目——**定检索维度**，这是库的骨架。

## 第三步：复述确认（防理解偏差）

> "我理解你要的是：把【①】从【②】里捞出来，整理成能按【③】搜到的库。对不对？"

- 说"对" → 才开始动手。
- 说"不对" → 重问，别硬上。

## 防坑边界（重要）

- **一次只接 1 人的 1 类资料。** 别一人全包、别三人齐上——你时间摆不平（快递点 + 俩娃 + 军事号 + 读书号日更）。
- **首轮交付物就一个：** 一个能搜的最小知识库（哪怕只有 20 条），先跑通再扩。
- **收需求不超过 20 分钟。** 超了说明对方自己也没想清，让他先想，别替他想。

## 收口

发圈是动作，收需求是交付的真正起点。这步做扎实，后面搭库才不会返工，也不会变成免费劳力还帮不出效果。
